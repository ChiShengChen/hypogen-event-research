# 否決模式 Harness

指引修正算術的第二種 Harness 模式。原本的擷取模式不變，仍是預設。

| 模式 | 模型呼叫 | 程式做什麼 |
|---|---|---|
| `extract`（預設） | 擷取：只抄原文 | 核對引文後用 Decimal 計算，無法證明的運算元讓題目變 unknown |
| `veto` | 純 Astra：直接作答並逐欄引用 | 保留模型答案，只在模型自己的引文有**正面證據**顯示口徑不符時改為 unknown |

```bash
GUIDANCE_HARNESS=veto    # 或 extract；未設定時為 extract
```

切換點在 [guidance_harness.py](../../benchmarks/guidance_harness.py)，否決規則在 [guidance_veto.py](../../benchmarks/guidance_veto.py)。既有的 v2、累計期間與跨頁表格 runner 都維持原本的擷取行為。

## 否決規則

只檢查模型自己引用的運算元：

| 規則 | 觸發條件 | 例子 |
|---|---|---|
| 口徑 | 指引指向營收組成或非營收指標 | Subscription revenue、Product revenue、ARR、billings、comparable sales |
| 增率 | 指引只有成長率，沒有美元金額 | Total sales to increase 2.5% to 3.5% |
| 幣別 | 固定匯率或非美元 | Net sales (cc)、€ |
| 時點 | 引用案例以外的文件 | |
| 缺運算元 | 作答題目依賴的運算元沒有引用 | 答了前次隱含 Q4，卻沒引用前次 Q3 指引 |

找不到引文或讀不出金額**不會**否決。這是和擷取模式的關鍵差別：擷取模式在證明不了時棄答，所以在純 Astra 會的題目上只能打平或輸；否決模式只在有反證時介入，模型答對的題目不會被拉下來。

否決只影響依賴該運算元的題目。例如只有前次指引是訂閱營收時，最新隱含 Q4 仍保留模型答案。

## 開發集重播

重新評分[累計期間](../guidance-ytd/README.md)與[跨頁表格](../guidance-table/README.md)兩輪已封存的 24 案，零新增模型呼叫。純 Astra 組直接用封存回覆，否決組是同一份回覆加上否決，擷取組是封存的擷取回覆經過目前最新的跨頁表格核對器。每案沿用該輪封存的評分規則；重播的純 Astra 分數與兩輪公布的結果一致。

| 24 案 | 純 Astra | 否決模式 | 擷取模式（最新核對器） |
|---|---:|---:|---:|
| 數值與方向全對 | 20 | **23** | **23** |
| 含引文全對 | 17 | 19 | 17 |
| 誤調（該 unknown 卻給數字） | 4 | 1 | 0 |
| 誤棄答（該給數字卻 unknown） | 0 | 0 | 1 |

否決組與純 Astra 用同一份回覆，不一致的案例全部來自否決：數值全對 3 勝 0 負（精確雙尾 p = 0.25），含引文全對 2 勝 0 負。

| 案例 | 純 Astra 的錯 | 否決依據 |
|---|---|---|
| Workday | 用訂閱營收指引算出 Q4 | 三個指引引文都是 Subscription revenue |
| Snowflake | 用產品營收指引算出 Q4 | 三個指引引文都是 Product revenue |
| Walmart | 把固定匯率成長率換成美元 | 三個指引引文都是 (cc) 增率 |

12 個正例沒有任何否決。

### 解讀限制

- **這是樣本內結果。**規則是看過 Workday、Snowflake、Walmart 的失敗後寫的，只能說明規則能修正已知錯誤且沒有誤傷這 24 案，不能說明它在新案例上更準。
- **擷取模式在這 24 案同樣是 23/24。**它的核對器也是在這些案例上逐步修出來的。擷取模式在累計期間那輪的含引文全對偏低，原因是最新核對器把累計實績記在表格證明（proofs），那輪的評分只讀引文清單，因此判為引文不足；數值全對。
- 否決組唯一的誤調是 UiPath：前次隱含 Q4 只用前次公告就能算出，封存答案卻把三題都定為 unknown。跨頁表格那輪的報告也指出這個爭議。
- 擷取模式唯一的誤棄答是 Salesforce 先導：同名百分比表缺美元倍率，核對器拒絕了有效的合併營收表。

## 下一步：新案例驗證

在新發行人上同時比較三組，每案兩次呼叫（擷取與純 Astra，否決組重用純 Astra 回覆）：

- 負例多收模型容易誤算的口徑陷阱：只給訂閱或產品營收指引、固定匯率增率、只有 ARR 或 billings。
- 正例要包含同時列出總營收與訂閱營收指引的公司，檢查否決會不會誤傷。
- 否決規則在挑選新案例前以 SHA-256 封存。

重現：

```bash
python -m benchmarks.guidance_veto_run --phase replay   # 需要本機 output/ 下的封存公告
```
