# 系統診斷：對照文獻看現在的問題

2026-11-23。依據為[文獻綜述](literature-review/README.md)、目前程式碼與各輪 benchmark 結果。方括號內是[證據卡](literature-review/cards-verified.jsonl)編號，可查到論文原文。改善做法見[專案建議](project-recommendations.md)。

核心主張是「比純模型更準」。問題分三層：**量測證據的方式**、**對外承諾的時點保證**，以及 **Harness 介入的位置**。

| 問題 | 系統位置 | 嚴重度 |
|---|---|---|
| 歷史回放分不出能力與記憶 | 盈利回放、`as_of` 提示 | 高 |
| 主要量尺是同家族的單一 LLM 評審，且沒有人工評分 | `hypothesis_pilot.py`、跨業務連動 benchmark | 高 |
| 沒有前瞻實績 | 前瞻佇列、假說的可查核預測 | 高 |
| 網路來源的可得時點與引文靠模型自己 | `discovery.py` | 高 |
| Harness 介入在前沿模型已經會的地方 | 盈利數字、指引驗證器、跨業務連動 | 中 |
| 迭代流程製造假進步，樣本太小 | V8→V10、驗證器逐案補規則 | 中 |

## 1. 量尺撐不起「比純模型更準」

### 1.1 歷史回放分不出能力與記憶

**系統**：盈利預測以 2019–2024 年的 10-Q 回放，模型是之後才訓練的 GPT-6.2 Astra，靠 `as_of` 提示宣告截止時點。

**文獻**：

- 叫 GPT-4o 忽略 2010 年以後的資訊，假截止點前後準確率仍是 97.6% 對 98.0%，真正截止後只有 40% [P386-c2]。
- 提示模型「假裝不知道」，與真正不知道仍有 52% 的落差 [P137-c1]。
- 只給 ticker 和日期，模型在截止前猜對 59.2% 的財報方向，截止後是 53.3% [P575-c2]。

**影響**：兩組都可能直接記得答案，Harness 的真實貢獻會被掩蓋或扭曲。現有的盈利回放 MAE 比較，都不能拿來支持準確度主張。

### 1.2 評審是主要量尺，卻最不可靠

**系統**：

- 假說與跨業務連動的 benchmark 由 Sol 單次判讀評分；
- [hypothesis_pilot.py](../benchmarks/hypothesis_pilot.py) 中評審是 `gpt-6.2-sol`，產生模型是 `gpt-6.2-astra`，兩者同一家族；
- 人工評分 0 案。

**文獻**：

- 同家族同系列的評審有約 8.9% 的偏好洩漏，不同系列是 2.8% [P320-c3]。
- 只改評審的提示措辭，就會翻轉四分之一到三分之一的判決 [P343-c4]。V8 到 V9 在相同證據下由 4.58 跳到 9.80，就是這個現象。
- 投行簡報研究中，分數變異有 59% 來自評審，只有 14% 來自被評的作品 [P1183-c3]。
- HindSight：評審給兩組系統 7.44 對 7.40，真實結果是 0.297 對 0.119 [P341-c4]。

**影響**：目前 Sol 評分的勝負都還不能算數。要證明評審可以取代人工，至少需要 3 位專家評 50 到 100 份 [P1334-c1]。即使如此，評審最多也只能把所需的人工標註減半 [P1352-c1]。

### 1.3 沒有前瞻實績

**系統**：前瞻佇列已封存 3 案，0 案揭曉。報告中的假說都寫了指標、方向、來源與截止日，卻從未拿真實結果核對。

**文獻**：

- 對尚未揭曉的問題作答、等結果出來再評分，才是黃金標準 [P17-c1]；
- 研究構想在構想階段的評分，與實際執行後的評分只有弱相關 [P335-c6]。

## 2. 產品的核心承諾「時點正確」有漏洞

**系統**：[discovery.py](../research_app/discovery.py) 有兩個問題：

- 網路來源的發布日期是**模型自己回報的**（`Candidate.published_on`），再以該日的 UTC 日末當作可得時點；
- 證據文字存的是**模型寫的摘要**（`text_format="summary"`），引文檢查比對的是模型摘要而不是原文，形成循環驗證。

**文獻**：

- 搜尋引擎的日期過濾，在 Google 有 71.0% 的題目、DuckDuckGo 有 81.2% 撈到截止後的重大資訊 [P872-c1]；頁面上標示的更新日期也不可靠 [P872-c3]。
- BuySideFlow 中，答案正確的執行有 50.8% 仍違反時點規則 [P667-c1]，規則式檢查器只抓到 34.9% 的違規 [P667-c5]。

**影響**：如果「時點正確」是賣點，這裡是最弱的一環。SEC 財報資料這條路徑反而做對了（見下文），問題集中在網路搜尋。

## 3. Harness 介入在前沿模型已經會的地方

**系統**：

| 題目 | Harness | 純 Astra |
|---|---|---|
| [指引修正算術](guidance-arithmetic/README.md)先導 | 96/96 | 96/96 |
| 盈利 EPS 平均絕對誤差 | 0.454 | 0.338 |
| 完整公告驗證器保留集 | 1/4 | 4/4 |
| 跨業務連動 V10 正例 | 2/4 | 4/4 |

**文獻**：

- EPSBench 換 harness 只讓 EPS 誤差變動 −0.004 到 +0.001 [P378-c2]；
- kw-bench 中，前沿模型上 harness 的差異消失（0.9986 對 1.000）[P671-c2]；
- 模型越強，harness 的增益越小：gpt-4.1 +0.405，gpt-5.4 只有 +0.091 [P1270-c4]。

**影響**：額外的規則與驗證步驟，主要帶來漏判與過度保守。文獻中 harness 確實領先的位置，系統還沒好好利用：

- 用確定性程式碼修正模型的系統性錯誤 [P1188-c6]；
- 補上模型拿不到的資料或工具：同一模型拿掉搜尋，準確率掉 11.0 到 14.2 個百分點 [P125-c7]；
- 讓較小的模型達到前沿模型的水準：27B 加 harness 和直接用 Opus 打平 [P1183-c2]。

## 4. 迭代流程製造假進步

**系統**：

- 提示從 V8、V9 改到 V10，驗證器逐案補規則（複數 `revenues`、多層表頭、左欄單位）；
- 先導通過、保留集失敗反覆出現；
- 沒有累計總試驗數；
- 多數輪次只有 4 到 8 案，每案只跑一次。

**文獻**：

- Hard to Fool：一個 Sharpe 接近 3 的規則，在保留集掉到 0.26 [P304-c2]。
- 出貨的金融 agent 研究：開發集的 +14 到了新題只剩 +1.5 [P84-c3]；依開發題寫的個案規則無法推廣 [P84-c4]；同一 agent 七次執行，149 項中通過 105 到 123 項 [P84-c1]。

**影響**：8 案中至少要有 6 案是「一方對、一方錯」且全部偏向同一方，McNemar 檢定才會低於 0.05。目前多數「領先兩案」或「落後兩案」都在雜訊範圍內。

## 做對的地方（文獻支持）

- **封存與預註冊，每輪換新的保留集。**在審計的 LLM 交易論文中，只有 9% 報告了依嘗試次數調整後的結果 [P627-c4]，本專案的做法高於領域平均。
- **SEC 財報採首次申報值。**[earnings_cases.py](../benchmarks/earnings_cases.py) 對每個期間取最早申報的數字，避開了文獻警告的重述問題：Enron 在 2002 年改寫了 1998–2001 的盈餘 [P17-c6]。
- **Decimal 確定性計算與引文核對框架。**這是最有機會證明 Harness 真正「更準」的基礎。指引修正算術先導中，Harness 的 48 次數字引用全部通過機械核對。

## 最優先修正的三件事

1. **換量尺。**準確度主張改用確定性評分或前瞻實績；收集第一批人工評分，先由 3 位分析師評現有的 20 個配對。
2. **補時點。**保存網頁原文，可得時點改用可驗證的來源，例如 EDGAR 受理時間或網頁存檔的擷取時間。
3. **換戰場。**集中在文獻顯示 Harness 能贏的題型。指引修正算術 v2 正在做：跨文件推算隱含季度，加上不說明比較基準的開放問法。
